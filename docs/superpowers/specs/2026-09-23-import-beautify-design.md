# 导入一键美化（Markdown Beautify）设计

- 日期：2026-09-23
- 项目：Folio（单文件 `index.html`，离线前端）
- 状态：设计已确认，待实现

## 1. 概述

用户的主要场景是**从 AI 复制 Markdown 文本再导入 Folio 使用**。这类文本常带有排版混乱与复制残留（多余空行、行尾空格、标题层级跳跃、中文间被插入空格等）。本功能提供**一键美化**：把导入的文本按一套预设方案统一排版与字体，并清理明显残留。

已与用户确认的四项决策：

| 决策 | 选择 |
|---|---|
| 美化边界 | **排版字体 + 轻量清理**（纯视觉 + 清理明显残留，不改正文用词） |
| 交互与回退 | **载入后在编辑器里询问 + 可一键撤销**（真实编辑器即最准的预览） |
| 方案数量 | **三套可选**：清爽 / 公文 / 论文 |
| 触发范围 | **粘贴时主动询问 + 随时可手动套用**（工具栏命令） |

## 2. 三套预设方案

字号单位用 `pt`（浏览器在屏幕上按 1pt ≈ 1.333px 渲染，导出时与打印一致）。

| | h1 大标题 | h2 二级 | h3 三级 | 正文 | 行距 | 首行缩进 |
|---|---|---|---|---|---|---|
| **清爽** `clean` | 微软雅黑 粗 22pt | 微软雅黑 粗 16pt | 微软雅黑 粗 14pt | 宋体 12pt | 1.75 | 无 |
| **公文** `gov` | 方正小标宋简体 22pt | 黑体 16pt | 楷体_GB2312 16pt | 仿宋_GB2312 16pt | 固定 28pt | 2 字符 |
| **论文** `paper` | 黑体 18pt | 黑体 14pt | 黑体 12pt | 宋体 12pt | 1.5 | 2 字符 |

字体回退栈（与工具栏现有 `font-family` 取值保持一致）：

- 微软雅黑 → `"Microsoft YaHei", "微软雅黑", sans-serif`
- 宋体 → `"宋体", SimSun, serif`
- 黑体 → `"黑体", SimHei, sans-serif`
- 楷体_GB2312 → `"楷体_GB2312", KaiTi_GB2312, "楷体", serif`
- 仿宋_GB2312 → `"仿宋_GB2312", FangSong_GB2312, "仿宋", serif`
- 方正小标宋简体 → `"方正小标宋简体", FZXiaoBiaoSong-B05S, "方正小标宋", serif`

三套方案都**去掉编辑器默认的装饰线**（现有 `.editor h1` 的 `border-bottom` 与 `.editor h2` 的下划线）。

### 2.1 元素映射（哪些元素套哪一档样式）

| 元素 | 套用 | 首行缩进 |
|---|---|---|
| `h1` | 大标题 | — |
| `h2` | 二级 | — |
| `h3`、`h4`、`h5`、`h6` | 三级（四级及以下统一按三级处理） | — |
| `p` | 正文 | 按方案（公文/论文为 2 字符，清爽无） |
| `li` | 正文 | **不缩进**（列表已有自身缩进） |
| `td`、`th` | 正文 | **不缩进** |
| `blockquote` | 正文（保留其原有左缩进与左边线） | 不缩进 |
| `pre`、`code` | **不处理**（保持等宽字体与原始空格） | — |
| 其他（`img`、公式等） | **不处理** | — |

## 3. 轻量清理规则

三套方案**共用**同一套清理。清理**在 HTML 上执行**（而非 markdown 文本上），这样粘贴导入、文件导入、手动套用三条入口行为完全一致。

清理范围**排除** `pre`、`code`、`script`、`style` 内的文本。

| # | 规则 | 说明 |
|---|---|---|
| C1 | 删除空段落 | 移除内容为空或仅含 `<br>` / `&nbsp;` 的 `<p>`、`<div>` |
| C2 | 合并连续空行 | 把连续 3 个以上换行/空段落压成 1 个空段落 |
| C3 | 去行尾空格 | 文本节点内行尾空白（含全角空格 U+3000）清除 |
| C4 | 还原转义残留 | 文本节点中 `\` 紧跟 `* _ # [ ] ( ) ~ \` + - . !` 之一时，去掉反斜杠 |
| C5 | 去掉中文之间多余空格 | **仅当空格两侧都是中日韩字符**时删除该空格；中英之间、数字两侧的空格**保留** |
| C6 | 修正标题层级 | 见下方精确算法 |

**C6 精确算法**（`normalizeHeadings`）：

```
map = {}                               // 原始级别 -> 归一化级别
prev = 0
对 root 内按文档顺序的每个 h1..h6：
    o = 该标题的原始级别
    if o 已在 map 中:
        n = map[o]                     // 同一原始级别必须映射到同一级别
    else:
        n = min(o, prev + 1)           // 首标题归一为 h1；且不允许跳级
        map[o] = n
    h 改为 h{n}
    prev = n
```

**为什么用映射表而不是逐元素 clamp**：逐元素计算会把**同级兄弟打散**。例 `## 第一章` / `### 1.1` / `### 1.2` / `#### 1.2.1` 若逐元素压制，`1.1` 被压成 h2 后 `1.2` 会留在 h3——两个同级小节变成不同级别，文档结构被破坏。映射表保证「原来是同级的，归一化后仍然同级」。

例：`## A` / `#### B` / `### C` → `# A` / `## B` / `### C`；`## 第一章` / `### 1.1` / `### 1.2` / `#### 1.2.1` → `# 第一章` / `## 1.1` / `## 1.2` / `### 1.2.1`。

**明确不做**（会改动用词，风险高）：删除 AI 开场白/结束语、删除装饰 emoji、统一全角半角标点。

## 4. 交互设计

### 4.1 粘贴导入后的询问条

`载入文本` 载入原文后，在编辑器顶部浮出一条**询问条**：

```
✨ 要一键美化这篇吗？   [ 清爽 ] [ 公文 ] [ 论文 ]   [ 不用了 ]
                                            ☐ 以后自动套用「清爽」
```

- 点任一方案 → 立即套用；询问条变为状态条：`✓ 已美化（公文）  [ 撤销 ]  [ 换方案 ]`
- 点「不用了」→ 询问条消失，**本文档不再询问**（不写入全局设置）
- 勾「以后自动套用 X」→ 写入全局设置，之后粘贴导入直接套用、不再询问；X 取用户最后一次套用的方案（首次默认「清爽」）
- 询问条只对**本次粘贴产生的文档**出现一次
- **自动套用模式**（`auto: true`）下不再出现询问条，但仍显示状态条 `✓ 已美化（清爽）  [ 撤销 ]  [ 换方案 ]`，保证随时可撤销

### 4.2 随时可手动套用

工具栏新增「美化 ▾」按钮（复用现有 `.dd` 下拉模式），菜单项：

- 三套方案：清爽 / 公文 / 论文
- 分隔线
- 开关：`粘贴导入时自动套用`（对应全局设置）

手动套用对**当前文档**生效，与导入来源无关（文件导入、拖拽导入、手动编辑的文档都可以）。

### 4.3 撤销

- 套用美化前，记录该文档的**原始 HTML**（只记最初一份）
- **再次套用别的方案时，不覆盖这份原始记录**——「撤销」始终回到美化之前的原始状态
- 撤销入口在下列任一情况**失效并隐藏**：
  - 用户点击「撤销」（撤销后清除记录）
  - 用户编辑了文档内容（此时回退会吞掉编辑）
  - 切换离开该文档后再回来（除非内容仍与美化结果一致）
- 判定方式：记录 `{ docId, originalHtml, appliedHtml }`；仅当 `activeDocId === docId` 且 `当前内容 === appliedHtml` 时显示撤销入口

## 5. 架构

### 5.1 为什么必须用内联样式

美化通过**给内容元素写入内联样式**实现（`style="font-family:...;font-size:...;line-height:..."`），**不是**改编辑器 CSS。原因：导出 Word 时只认内联样式，纯 CSS 样式导不出去——用户会得到一份没有排版的 Word。

装饰线（边框/下划线）这类**只影响屏幕与 PDF** 的部分，通过编辑器根节点上的类名关闭（`#editor.bz-clean / bz-gov / bz-paper`）。

### 5.2 组件划分

| 单元 | 职责 | 依赖 |
|---|---|---|
| `BEAUTIFY_PRESETS` | 三套方案的常量表（字体/字号/字重/行距/缩进/间距） | 无 |
| `cleanupHtml(root, opts)` | HTML 清理（C1~C6），纯 DOM 操作，返回统计 | 无 |
| `applyPreset(html, presetKey)` | 清理 + 写内联样式 + 关装饰，返回新 HTML 与统计 | `cleanupHtml` |
| `beautifyDoc(docId, presetKey)` | 应用到指定文档：记录撤销状态、写回 `docs[]`、刷新编辑器与标签 | `applyPreset` |
| 询问条 UI | 导入后询问、状态显示、撤销 | `beautifyDoc` |
| 「美化 ▾」工具栏菜单 | 手动套用 + 自动套用开关 | `beautifyDoc` |
| `loadBeautifyCfg / saveBeautifyCfg` | 全局设置持久化 | `safeSet` |

### 5.3 数据与存储

全局设置存入现有存储层：

```
folio.beautify = { preset: "clean" | "gov" | "paper", auto: true | false }
```

使用 `safeSet` 写入（沿用 2026-09-23 建立的存储安全层），并纳入现有**导出/导入备份**。

文档上的标记（仅用于 PDF 面板提示，不参与渲染）：

```
docs[i].beautifyPreset = "clean" | "gov" | "paper"
```

套用时写入，撤销时清除。

## 6. 与 PDF 导出面板的交互

美化写入的是**绝对字号**，而内联样式优先级高于 PDF 面板的 `.editor { font-size }`。因此：

- 当当前文档带有 `beautifyPreset` 时，PDF 面板的「**字号**」「**行距**」两个下拉**置灰**，并显示提示：`本文已套用「公文」样式，字号与行距由样式决定`
- 「纸张」「边距」不受影响，始终可用

这是已与用户确认的取舍：换来的是 Word 导出能保留标题层级的大小差异（若改为让面板统一控制字号，Word 导出会丢失层级）。

## 7. 边界与错误处理

- **空文档**：无内容时不套用，提示「内容为空」；撤销记录不建立
- **无标题的文档**：C6 无操作；排版仍应用于正文
- **文档只有一个标题**：C6 把第一个标题平移到 h1
- **标题超过 6 级**：clamp 到 h6
- **`pre` / `code` 内容**：清理与排版**均不触碰**（保持代码原样，尤其不能改字体族与缩进）
- **表格**：正文排版应用到表格单元格内的段落，但**不设首行缩进**（表格内缩进会很难看）
- **图片 / 公式**：不处理，保持原样
- **撤销入口失效后的再套用**：允许（会重新记录原始 HTML——此时「原始」指当前状态）
- **多次套用**：第二次套用前会先把「最初原始 HTML」保留不变，确保撤销回到真正的原始

## 8. 测试要点

- 三套方案分别套用后，抽查 h1/h2/h3/正文的 `font-family` 与 `font-size` 是否符合常量表
- C1~C6 每条规则各一个用例（含 `pre`/`code` 内**不应**被改的反例）
- C5 反例：`中文 English 中文` 里的空格**必须保留**
- C6 用例：`## A` / `#### B` / `### C` → `# A` / `## B` / `### C`
- 撤销：套用 → 撤销 → 内容与美化前逐字符一致
- 撤销失效：套用 → 编辑一个字符 → 撤销入口消失
- 换方案：套用「清爽」→ 换「公文」→ 撤销 → 回到**最初**原始内容（不是「清爽」）
- 导出 Word：美化后的文档导出 `.docx`，标题字号层级被保留
- 导出 PDF：美化后导出，标题/正文字体与字号符合方案；同时确认界面元素仍无泄漏
- 自动套用：勾选后再次粘贴导入，直接套用且不出现询问条
- 备份：导出/导入备份后 `folio.beautify` 保留

## 9. 非目标（YAGNI）

- 不做自定义方案（用户未提出；三套已覆盖「看资料 / 交文件 / 写论文」）
- 不做自动语义清理（删开场白 / emoji / 标点统一）——会改动用词，风险高
- 不做 markdown 级的清理与 HTML 级双份逻辑（统一在 HTML 上做）
- 不做美化历史 / 多版本样式回溯（撤销回到原始已足够）
